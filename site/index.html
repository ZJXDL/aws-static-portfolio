01 / PROJECT OVERVIEW

The goal

A simple website, built with real infrastructure practices.

The goal was to publish a static site without making its storage bucket public or running a web server. The result is a small AWS architecture that separates private origin storage from public content delivery.

OpenTofu defines the infrastructure as code. GitHub Actions publishes site changes to S3, while CloudFront handles HTTPS, caching, and delivery. The workflow uses OpenID Connect (OIDC) to request short-lived AWS credentials; no long-lived AWS access key is stored in GitHub.

02 / ARCHITECTURE

How a request moves

CloudFront is the public entry point; S3 remains private.

02 · EDGECloudFrontCache · TLS · headers

03 · AUTHENTICATE ORIGINOACSigV4 signed request

04 · ORIGINPrivate S3HTML · CSS · JavaScript

When a visitor requests a page, CloudFront first checks its cache. On a cache miss, Origin Access Control (OAC) signs the request with AWS Signature Version 4 and sends it to the S3 REST origin. The bucket policy permits s3:GetObject only when the request comes from this CloudFront distribution. S3 returns the object to CloudFront, which serves it to the visitor over HTTPS.

The S3 static website endpoint is not used. The bucket is therefore not exposed as a public website origin, and the same CloudFront distribution applies TLS and response security headers.

04 / SECURITY DESIGN

Guardrails by default

Controls are applied at storage, origin access, and delivery.

PRIVATE ORIGIN

No public S3 access

S3 Block Public Access stays enabled. The bucket policy allows only s3:GetObject from CloudFront when the source ARN matches this distribution.

ENCRYPTED CONNECTIONS

HTTPS to visitors

HTTP requests redirect to HTTPS. The CloudFront viewer policy requires TLS 1.2 or newer, using the default CloudFront certificate.

RESPONSE HEADERS

Browser protections

The response policy sets HSTS, Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, and Referrer-Policy headers.

DATA PROTECTION

Encryption and recovery

Objects use SSE-S3. Versioning preserves previous copies, while lifecycle cleanup bounds noncurrent-version retention to 30 days.

The redesigned page uses system fonts, but the current Content Security Policy still permits Google Fonts from an earlier version. Removing those allowances would tighten the policy further.

05 / DEPLOYMENT & OPERATIONS

How to manage it

Provision, publish, update, and tear down.

PROVISION INFRASTRUCTURE

Run from the repository's infra/ directory:

tofu init
tofu plan
tofu apply

Review the plan before approving an apply. The CloudFront distribution can take several minutes to deploy.

PUBLISH SITE FILES

Push a change under site/ to main, or run “Deploy portfolio” from GitHub Actions. The workflow requests short-lived AWS credentials, syncs the files to S3, and invalidates CloudFront's cache.

git add site/
git commit -m "Update the case study"
git push

The IAM role can publish this site's files and invalidate this distribution. It cannot change the infrastructure.

DESTROY THE STACK

When the project is no longer needed:

cd infra
tofu destroy

The dedicated bucket has force_destroy enabled so OpenTofu can remove its contents. Do not store unrelated files in it.

Current delivery status

Automatic deployment is active. GitHub Actions assumes a dedicated AWS IAM role through OIDC, syncs site/ to the private S3 bucket, then clears the CloudFront cache. The workflow was verified with a successful deployment.

06 / TRADEOFFS & NEXT ITERATION

Possible next improvements

A small project should make its limits visible.

Local OpenTofu state: simple for a learning project, but a team deployment should use encrypted remote state with locking and access controls.

Broad cache invalidation: invalidating /* keeps this small site's workflow simple. A larger site could use versioned assets and more targeted invalidations.

No custom domain: the default CloudFront domain avoids DNS and certificate setup. A production branded site could add a domain and an ACM certificate.

Monitoring: the stack focuses on secure delivery. A next iteration could add alarms, access logging, and a documented recovery exercise.

Cost: S3 and CloudFront usage can incur charges. The distribution uses PriceClass_100; account usage and current AWS pricing should be reviewed before leaving the site online long term.

PROJECT SUMMARY

A small system with real cloud boundaries.

Visitors get a fast HTTPS site. The origin stays private. Infrastructure is reproducible, and security and operational tradeoffs are documented alongside the implementation.
