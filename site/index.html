01 / THE IDEA

What did I build?

The short version, before the details.

This project puts a simple website on AWS without exposing its storage bucket to the public internet. Visitors connect to CloudFront, a content delivery network. CloudFront reads files from a private S3 bucket and sends them back over HTTPS.

The infrastructure is written as code with OpenTofu. A GitHub Actions workflow publishes website changes automatically. It uses OpenID Connect (OIDC) to receive temporary AWS credentials, so no permanent AWS access key is saved in GitHub.

In one sentence: private storage, secure public delivery, repeatable infrastructure, and an automated update path.

A SIMPLE WAY TO PICTURE IT

A library, a locked archive, and a courier

Imagine the website files are books in a locked archive. The archive is S3. CloudFront is the library desk visitors can reach. It fetches a book from the archive only when it is allowed, then keeps a nearby copy ready for the next reader.

GitHub Actions is the delivery service that brings updated pages to the archive. AWS gives it a short-lived badge after checking which project and branch asked for access.

The analogy helps with the big picture. The sections below describe the actual AWS controls and request flow.

THE DESIGN QUESTION

Why not put the files on a public bucket?

A simple site still deserves a clear boundary.

01

Keep storage private

S3 is the source of the files, but visitors cannot browse the bucket directly. Public access is blocked at the bucket level.

02

Make one controlled entrance

CloudFront is the public entry point. It handles HTTPS, caching, compression, and browser security headers.

03

Let only that entrance read

Origin Access Control signs CloudFront’s request. A bucket policy checks that it came from this exact distribution.

What happens on a cache miss?

  1. The browser asks for a page. The request uses HTTPS, so the connection to CloudFront is encrypted.
  2. CloudFront checks its cache. If it already has a fresh copy, it can respond without asking S3. This is a cache hit.
  3. On a cache miss, CloudFront goes to S3. It signs the request with OAC. A visitor cannot copy this signed request and use it to browse the bucket.
  4. S3 checks the bucket policy. It allows the CloudFront service to read objects only when the request names this distribution as its source.
  5. CloudFront returns the file. It applies the configured response headers and sends the file over HTTPS. It can keep a cached copy for later requests.
↳

Why use the S3 REST origin?

This project does not enable S3 website hosting. CloudFront connects to the bucket’s regular S3 endpoint and uses OAC. That combination supports a private bucket; the S3 website endpoint does not use OAC.

03 / A CODE CHANGE GOES LIVE

How automatic publishing works

A push to main is the starting signal.

01 · CHANGE

Update a site file

Edit HTML or CSS under site/ and push it to main. The workflow can also be started manually from GitHub Actions.

02 · CHECK

GitHub proves its identity

GitHub Actions requests an OIDC token. AWS checks its audience and its exact repository-and-branch subject.

03 · AUTHORIZE

AWS issues temporary credentials

A dedicated IAM role permits this repository’s main branch to publish the site. The credentials expire automatically.

04 · PUBLISH

Files sync; cache clears

The workflow syncs site/ to S3, removes stale site files, then asks CloudFront to invalidate /*.

SECURITY DETAIL

No permanent AWS access key is stored in GitHub. The deploy role can update website objects and invalidate this distribution; it cannot create or change AWS infrastructure.

Technical details of the deployment role

The OIDC audience is sts.amazonaws.com. The trust subject is limited to repo:ZJXDL@192978802/aws-static-portfolio@1414794721:ref:refs/heads/main, tying access to this owner, repository, and branch.

The inline permissions are s3:ListBucket, s3:ListBucketMultipartUploads, s3:PutObject, s3:DeleteObject, s3:AbortMultipartUpload, s3:ListMultipartUploadParts, and cloudfront:CreateInvalidation. S3 actions are scoped to this bucket and its objects; invalidation is scoped to this distribution.

The workflow uses actions/checkout@v7.0.1 and aws-actions/configure-aws-credentials@v6.3.0. The IAM role and OIDC provider are configured in IAM separately from the ten OpenTofu-managed resources.

05 / SECURITY & TRUST BOUNDARIES

What is protected, and how?

Security is a set of specific checks, not a label.

STORAGE

The bucket is not public

Block Public Access is enabled. The bucket policy does not grant anonymous visitors access.

ORIGIN

CloudFront has a signed pass

OAC signs requests. The bucket policy checks the CloudFront distribution ARN before allowing reads.

VISITOR CONNECTION

HTTPS is enforced

HTTP is redirected to HTTPS. The distribution requires TLS 1.2 or newer and uses CloudFront’s default certificate.

BROWSER

Responses carry safeguards

Headers set HSTS, deny framing, prevent MIME sniffing, and set a Content Security Policy and Referrer-Policy.

STORED FILES

Encryption and versions

S3 encrypts objects at rest and keeps previous versions. A lifecycle rule removes old versions after 30 days.

DEPLOYMENT

GitHub gets limited access

The trust policy accepts only ZJXDL/aws-static-portfolio on main. The role can list this bucket, upload or delete its site objects, and invalidate this distribution.

Response header settings

HSTS uses a one-year max age with subdomains and preload enabled. The policy also sets X-Frame-Options: DENY, X-Content-Type-Options: nosniff, and Referrer-Policy: strict-origin-when-cross-origin. The Content Security Policy restricts scripts and default resources to this site, blocks embedded objects, and forbids framing.

A known improvement

The page uses system fonts and does not load Google Fonts. The deployed Content Security Policy still allows Google Fonts hosts from an earlier design. Removing that unused allowance would tighten the policy.

06 / OPERATING THE PROJECT

Change it, inspect it, remove it

The steps a maintainer actually needs.

01

Publish a site change

From the repository root, commit and push files in site/. GitHub Actions publishes them automatically.

git add site/
git commit -m "Update the website"
git push

To retry or deploy manually, start “Deploy portfolio” in the repository’s Actions tab.

02

Change infrastructure

From infra/, OpenTofu compares the code with the known state and proposes changes.

tofu init
tofu plan
tofu apply

Review the plan before applying it. The GitHub deploy role cannot perform this step.

03

Remove the project

From infra/, destroy the stack when it is no longer needed.

tofu destroy

Warning: the dedicated bucket uses force_destroy. Destroying the stack deletes its website files and stored versions.

07 / LIMITS & NEXT STEPS

What this project does not do

A useful case study is honest about its edges.

State is local. OpenTofu state lives on the operator’s computer and is ignored by Git. A team setup should use protected remote state with locking and backups.

No custom domain. Visitors use the default CloudFront address. A branded domain needs DNS and an ACM certificate configured for CloudFront.

Monitoring is minimal. This stack does not configure access logs, alarms, or an incident response process.

Cache clearing is broad. The workflow invalidates /* after each deployment. A larger site could use versioned assets and more targeted invalidations.

Costs depend on use. S3 and CloudFront can incur charges based on requests and data transfer. Review current AWS pricing and set a budget alert.

It is a static site. There is no application server, API, database, user login, or dynamic content in this project.

A SMALL GLOSSARY

Cloud terms, in everyday words

A quick reference for first-time readers.

Static website
Pages made from files such as HTML and CSS. A server does not build each page when someone visits.
Amazon S3
A service for storing files as objects in buckets.
CloudFront
A content delivery network that serves copies of content from locations closer to visitors.
Origin
The source CloudFront reads from. Here, the origin is the S3 bucket.
Cache
A temporary nearby copy. Reusing it can make later requests faster and avoid a trip to S3.
OAC
Origin Access Control. It signs CloudFront’s requests so a private S3 bucket can verify the reader.
OpenTofu
A tool that describes infrastructure in files and applies planned changes to cloud resources.
OIDC
OpenID Connect. Here, it lets GitHub prove a workflow’s identity to AWS and request temporary access.
IAM role
An AWS identity with permissions that a trusted service or workflow can temporarily use.
CloudFront invalidation
A request telling CloudFront to remove selected cached copies so newer files can be fetched.
Region and edge
The S3 bucket is in the us-east-1 region. CloudFront is a global service with edge locations around the world.
Infrastructure as code
Infrastructure described in editable files, so changes can be reviewed and repeated.
